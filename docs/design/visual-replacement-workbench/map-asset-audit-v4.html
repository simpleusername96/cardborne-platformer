Three light-gray hangar directions

Concept status: ImageGen exploration only. Each image used the canonical style sheet as an actual reference together with the current runtime capture. The sheet supplied style grammar only; no depicted object or layout is approved or copied into production.

Quiet Grid

  • Closest to the current 288-unit grid.
  • Thin seams preserve orientation without making every tile a card.
  • Lowest implementation risk.

Wide Slabs

  • Fewer repeated seams and broader movement lanes.
  • Strong industrial-hangar read without service rails.
  • Requires fixed-scale tiled UVs rather than fitting one square texture.

Shared constraints
No cyan frame, service rail, decorative lane, nested outline, rivet field, random scratch, texture noise, or per-cell light.
Retained identity
The approved pale wall language, circular repair/overdrive pads, bulkhead state silhouettes, amber rewards, and dark exterior void remain.
Visibility target
Walls and cover must read in grayscale; projectiles and the smallest XP pickup must remain identifiable at the full-map camera scale.

The walls in these generated scenes show only the intended pale mass and contrast. They are not replacement wall assets; production retains world_wall_segment_9.png and corrects only its placement.

Recommended change set

Proceed with Near-Solid Bay as the target direction. It best matches the requested hierarchy: one quiet light-gray hangar deck, clearly visible pale walls, and gameplay objects carrying the color. Its generated scuffs, stray seams, and projectile trails are explicitly excluded from production.

  1. Update the visual contract before asset generation: replace the current “dark floor” requirement with the selected cool light-gray hangar direction while preserving sparse 3–5-plane geometry.
  2. Generate one seamless floor master, one simplified isolated-cover master, and the three Wear Tile states in one authority-grounded batch. Keep wall, repair pad, overdrive pad, and bulkhead identities.
  3. Simplify composition code: fixed-scale floor UVs, fixed-scale wall repetition, one Arc corridor with no seven-copy ornament, and one Transit progress treatment.
  4. Re-author and enlarge the XP master in the same review batch; projectile enlargement remains a separate combat-visibility unit even though it is shown in the concepts.
  5. Publish exact AS-IS/TO-BE comparisons at runtime scale, then switch only the selected direction. Run the full native/Web and collision-overlay validation after the complete visual batch.
