무엇을 먼저 읽게 할 것인가

단독 `+`나 위 화살표는 빠르지만 “무엇이 늘어나는지”를 설명하지 못합니다. 그래서 고유 업그레이드는 동작 자체를, 여러 무기에 공통 적용되는 강화만 기존 계열 본체와 modifier의 조합으로 표현했습니다.

  3. 03수치는 굽지 않음: 레벨과 정확한 증가량은 기존 텍스트 UI가 소유하므로 이미지에는 숫자를 넣지 않습니다.
  4. 0448px 우선: 작은 원·입자·글자 대신 1개 dominant silhouette와 1–2개 보조 의미만 남깁니다.
  5. 05색은 보조: 원소색과 amber는 의미를 강화하지만, 탄환 수·관통·얼음·광선·자석 형상만으로도 구분합니다.
  • Microsoft Fluent 2 Iconography — literal metaphor를 우선하고, modifier는 필요할 때 우측 하단에 두며 복잡해지면 쓰지 말라는 원칙.
  • Google Material Symbols — 작은 크기에서도 optical size와 weight를 조절해 인지성을 유지하는 사례.
  • Path of Exile · Skill/Support interactions — 추가 투사체와 volley를 실제 투사체 수·배치로 구별하는 사례.
  • Hades 공식 업데이트 — 공격력·속도·범위·지속시간을 서로 다른 효과 축으로 취급.
  • Warframe 공식 패치 노트 — 유도 미사일·궤도 무기·범위 효과처럼 행동이 다른 무기를 독립적으로 설명.

레퍼런스에서 가져온 것과 가져오지 않은 것

외부 레퍼런스는 인지 관례만 정했습니다. 다른 게임의 아이콘, 실루엣, 색 배치나 장식은 복제하지 않았습니다.
