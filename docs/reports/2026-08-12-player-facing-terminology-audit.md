# 플레이어 노출 용어 전수 감사

## Purpose

게임이 기능을 바로 알려 주는 보편적인 용어 대신 설정 문구, 조어, 서로 겹치는
동의어를 과도하게 쓰는지 확인했다. 이 문서는 현재 용어의 문제와 권장 방향을
기록하는 근거 문서다. 아직 합의하지 않은 적·보스·업그레이드의 고유 명칭을 이
문서만으로 일괄 변경하지 않는다.

## Sources

- `localization/vehicle_stage.csv`: 현재 한국어·영어 플레이어 노출 문자열 392개.
- `scripts/ui/`, `scripts/vehicle/vehicle_run.gd`: 실제 노출 위치와 상태 문자열 생산자.
- `scripts/cards/vehicle_upgrade_catalog.gd`와
  `scripts/progression/vehicle_guidebook_stat_adapter.gd`: 카드·가이드북의 의미 소유자.
- `docs/product/vehicle_game_spec.md`, `docs/product/vehicle_upgrade_catalog.md`,
  `docs/design/VISUAL_SYSTEM.md`: 제품·업그레이드·표현 계약.

감사 시작 시 현지화 행은 464개였다. 제거된 기능과 화면 문구 72개를 삭제한 뒤
392개가 남았다. 외부 게임 조사는 하지 않았다. 이번 판단은 유행하는 이름을 찾는
일이 아니라 현재 게임 안에서 의미를 빠르게 전달하고 같은 개념을 같은 말로 쓰는지
검증하는 일이기 때문이다.

## Findings

### 1. 같은 개념에 여러 단어를 쓴다

현재 한국어 문자열에는 `기체` 9회, `차체` 5회, `선체` 1회, `차량` 1회가
공존한다. 보호 자원도 `방벽` 3회와 `방어막` 5회가 섞여 있다. 성장 선택은
`모듈` 13회, `회로` 1회, `업그레이드` 2회로 표현한다. 이는 서로 다른 시스템처럼
오해하게 만들지만 현재 런타임 계약에는 그만큼 명확한 구분이 없다.

권장 기본값은 다음과 같다.

| 의미 | 권장 표시 | 피할 표시 | 이유 |
| --- | --- | --- | --- |
| 플레이어 조종체 | 기체 / Ship | 차량, 선체를 같은 의미로 혼용 | 현재 화면과 가이드에서 가장 많이 사용 |
| HP | 내구도 / Hull | 장갑·차체·선체를 임의 조합 | 수치의 기능이 즉시 보임 |
| 추가 보호 HP | 방어막 / Barrier | 방벽과 방어막 혼용 | 보편적이며 상태 자원으로 읽힘 |
| 런 중 성장 선택 | 업그레이드 / Upgrade | 모듈, 회로를 일반 분류명으로 사용 | 사용자가 바로 아는 상위 개념 |
| 진행 단위 | 스테이지 1–5 / Stage 1–5 | 작전 구역, 구역, 심층 | 현재 구조를 정확히 표현 |
| 기본 공격 | 기본 주무기 / Primary Weapon | 중립형 펄스 캐논 | 기능을 바로 설명 |

### 2. 상태가 아니라 세계관 해설처럼 읽히는 UI가 있었다

`빌드 정체성은 맵의 업그레이드에서 결정됩니다`는 조작이나 현재 상태를 설명하지
않는 메타 문구다. `증원 조립소 · 대기`와 충전·현장·조립 백분율 문자열은 플레이어가
지금 할 행동보다 내부 시설 상태를 앞세웠다. 이 문구들은 화면과 현지화에서 제거했다.
시설이 등장하거나 파괴될 때 무엇을 해야 하는지 알려 주는 짧은 알림은 실제 요소
설명이므로 유지했다.

이 구분을 이후에도 적용한다.

- 유지: 조작법, 효과, 수치, 위험, 목표, 즉시 필요한 행동.
- 제거: 빌드 철학, 개발·디버그 상태, 내부 처리 단계, 분위기만 더하는 상태 문장.
- 축약: 같은 사실을 제목·부제·설명에서 반복하는 문구.

### 3. 고유명처럼 보이지만 역할을 알려 주지 않는 이름이 많다

`리벳 추격자`, `기록고 리바이어던`, `왕관 엔진`, `변칙 장치`와
여러 업그레이드 이름은 SF 분위기를 만들지만 첫 조우에서 행동을 예측하기 어렵다.
반대로 `추적 미사일`, `회전 날개`, `후방 기뢰`, `수리 지원기`, `요격 포탑`은
기능이 바로 보인다. 후자의 방식이 현재 게임의 빠른 전투와 더 잘 맞는다.

다만 적·보스 이름을 전부 일반명으로 바꾸면 개체 구분과 기억성이 떨어질 수 있다.
따라서 다음 일괄 변경은 결정권자의 승인 뒤 진행해야 한다.

- 일반 적: 행동 우선 이름으로 통일할지 결정.
- 보스: `역할 + 고유명` 혼합을 허용할지 결정.
- 필드 오브젝트: 실제 행동을 드러내는 이름으로 바꿀지 결정.
- 업그레이드: 카드명은 짧은 기능명, 설명은 효과 문장으로 분리할지 결정.

### 4. 영어도 같은 단순화 원칙이 필요하다

한국어만 단순화하면 두 언어의 정보 구조가 달라진다. `Primary Weapon`, `Stage 1–5`,
`Upgrade`, `Hull`, `Barrier`처럼 한 의미에 한 표준 용어를 쓰고, 고유명 허용 범위도
두 언어에 같이 적용해야 한다. 내부 ID와 리소스 경로는 저장 데이터와 코드 참조를
보호하기 위해 표시명 변경과 분리한다.

## Changes Applied in This Pass

- 폐기한 디버그 전용 전투 선택 화면의 UI, 런타임 분기, 스크립트, 검증기,
  캡처 항목과 표시 문자열을 제거했다.
- 시작 화면의 필드명, 중복 무장 제목, 메타 문구와 긴 설명을 제거했다.
- `중립형 펄스 캐논`을 `기본 주무기`, `Pulse Cannon`을 `Primary Weapon`으로 바꿨다.
- 15개 field-stage 표시값을 `스테이지 1–5` / `Stage 1–5`로 바꿨다.
- 시설의 상시 내부 상태 문자열과 서사형 결과 제목을 단순화했다.
- `증원 조립소` 표시명을 `적 생성 시설` / `Enemy Spawner`로 바꿨다.
- 폐기한 선택 화면에서만 쓰던 패턴 표시 문자열 51개를 삭제했다. 전투 패턴 ID와 동작은
  변경하지 않았다.

## Recommendation

기능 우선 이름을 기본안으로 채택하되, 보스처럼 기억성이 중요한 제한된 대상에만
짧은 고유명을 허용하는 혼합안을 권장한다. 다음 변경은 연결된 결정 체크리스트에서
용어표를 승인한 뒤 현지화 표시값만 먼저 바꾸고, 내부 ID 변경은 별도 필요가 입증될
때만 수행한다.

## Limitations

- 이번 감사는 문자열, 런타임 소비 위치와 문서 계약을 검토했다. 실제 신규 사용자
  이해도 테스트는 하지 않았다.
- 적·보스·업그레이드 147개 관련 행의 최종 이름은 제품 소유자의 취향과 기억성
  기준이 필요하므로 확정하지 않았다.
- `FIELD_*` 표시값은 현재 시작 화면에서 숨겨졌지만 가이드·개발 도구에서 다시 쓸 수
  있어 삭제하지 않았다.
