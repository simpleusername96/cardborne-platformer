Cardborne · In-Game System Audit

The game has rules. The rules are hard to see.

Your concerns are real. The map code is safer than it looks. But the map still feels repeated. Effects share the wrong shapes. Normal enemies can start attacks outside the screen. Late stages use too many enemy types. Boss phases add speed, but not enough new ideas.

01 · Short answer

Most of the report is confirmed.

One part needs a correction: map rules do exist. The real problem is that the player cannot read them, and the rules do not create enough visible change.

Map Partly true.

Safe, repeatable random placement exists. The large map shapes still look almost the same.

Effects Confirmed.

A shield and a damage aura both use the same mint ring. Many hit effects draw nothing.

Enemies Confirmed.

Normal attacks check range and clear sight. They do not check if the enemy is on screen.

Bosses Confirmed.

Each phase is faster, but it mostly changes the order of the same four attacks.

The first blocker is a product rule conflict. The current game document says no new map-generation system and no new boss-pattern family without a spec change. The requested direction needs that document to change before code work starts.

What is true now

Question Current truth Meaning
Is the map random? Yes, inside a fixed set of safe sockets and cover choices. The system is not missing. It is too fixed and too similar.
Do support fields move? Yes. Repair and overdrive pads already move after timed states. This good rule is hard to notice in the current map language.
Do item boxes move? No. Their position is chosen when the stage layout is built. A new finite relocation rule is needed.
Do mobile enemies chase? Yes. Mobile roles have pursuit movement. Fixed towers and mines do not move. The bigger fairness problem is off-screen attack start.
Are bosses immune? No. A sealed boss still takes 20% damage. The open window takes 155%. The problem is repeated work, not full immunity.

03 · Map and items

The map is safe, but it does not feel alive.

The code uses a seed. A seed is a number that can repeat the same random result. It picks one field, eight cover blocks, enemy sockets, six loose items, and eight boxes. It also checks walkable space and safe distance. This is good. The visible result is still too flat.

AS-IS

The three fields use almost the same large frame and center pattern.

Outer walls and inner structural walls use the same wall image.

Floor panels look like many dark UI cards. They are stronger than some game objects.

Boxes stay where the stage put them.

TO-BE

Keep safe random rules and repeatable retries.

Build maps from a small set of authored route modules.

Give outer wall, inner wall, cover, and special terrain a different clear shape.

Move only unopened, off-screen boxes. Never create free extra rewards.

Fresh full-field screens

Recommended choice: keep the mental map. Keep the outer wall and the main inner walls for the full run. Do not turn a wall into a heal pad, attack pad, or portal. Change small cover, enemies, boxes, and functional terrain at stage boundaries.

What should change, and when?

Time Keep Change Why
Full run Field identity, outer boundary, main route, main inner walls, opened bulkheads, worn tiles Nothing here The player can learn the place.
New stage Safe routes and clear spawn space Small cover set, fixed threats, loose items, normal boxes, terrain package The same place gets a new fight.
Timed Total reward budget Repair and overdrive pads; one unopened box at a time The player has a reason to move.
Never One shape = one game meaning Do not reuse one wall or ring for a different rule The game stays readable.

A better random map model

Let code choose and test authored parts. Do not let code invent the art.

STEP 1Run seed
Pick one field family.
STEP 2Permanent shell
Place boundary and main walls.
STEP 3Stage pack
Pick cover, threats, items, and terrain.
STEP 4Safety test
Check routes, distance, sight, and boss space.
STEP 5Timed moves
Move only approved off-screen objects.

Safe box relocation

Recommended box rule

  1. Keep a fixed reward budget for the stage.
  2. Every 50 seconds, select one unopened normal box.
  3. Move it only if it is off-screen and far from the player.
  4. Use a reachable socket that was not used recently.
  5. Never move the two boxes inside reward rooms.
  6. Do not replace a box after the player opens it.

Can Cardborne use external assets?

Yes. But a pack should be a source kit, not final art. The repository already has six audited Kenney source images and license copies. None is used directly in production.

Use this intake rule

  1. Save the official link and license.
  2. Save the source file hash.
  3. Select only the needed part.
  4. Adapt camera, size, shape, color, and edge style.
  5. Compare AS-IS and TO-BE at real game size.
  6. Approve the exact final file before runtime use.

Best first test

DithArt Free Sci-Fi Tileset

It has floors, walls, doors, shadows, and a Godot tile setup. Its pixel look must be adapted.

Low-risk reference

Warped Top-Down Tech Lab 2

It is listed as CC0. It is useful for structure tests, not direct style replacement.

Already audited

Kenney Space Kit and Space Shooter Remastered

The repository has license files and source hashes for the selected samples.

Do not do this

Do not copy a whole pack into production. Do not use a store preview as an asset. Do not use a pack with unclear or mixed license text.

04 · Effects

Game meaning needs a small shape language.

The first goal is not beautiful effects. The first goal is complete and stable meaning. One rule should always use one base shape. A different rule should use a different base shape.

AS-IS

The barrier is a mint ring at radius 61.

Ion Field is also a mint ring, only larger.

Many projectile hits, weapon hits, enemy deaths, and pickups are set to “show nothing.”

The effect event does not carry a clear player or enemy owner field.

TO-BE

Use simple code shapes first.

Give every effect a base shape, owner sign, live size, and life phase.

Keep the base shape for the same effect.

Change both color and a small notch or direction mark for player and enemy ownership.

Minimum effect set

BarrierTight broken ring that hugs the bodyAmber outer notchCoral inward notch
Damage auraLarge filled disk plane with inward teethAmber source markCoral source mark

HealPlus shape and one short riseTeal plusNot used unless an enemy truly heals

Two-team hazardFull live area with two-way teethNeutral base plus danger edge; same damage rule for both teams
EMPOne broad broken pulse ringCyan system pulseEnemy EMP would keep shape and add coral owner marks
Phase 0 matches the requested direction. Use basic shapes for every important effect. Do not polish them yet. First prove that players can name the rule and owner in one second.
  1. Add four fields to the event data: effect type, owner, live size, and phase.
  2. Map every important event to one basic shape. Stop hiding hit and kill feedback.
  3. Use one owner mark for the player and one for enemies.
  4. Capture all effects in one comparison sheet.
  5. Test in grayscale and in a crowded fight.
  6. Only then spend time on final authored art for the few large effects.

Choose one cell at a time. Do not keep a weak cell only because another cell on the same sheet is good.

06 · Enemies

Normal enemies should enter the screen before they start an attack.

Current normal attacks use distance and clear sight. They do not require the enemy body to be visible. Mobile pursuit already exists. The fix belongs in attack permission, not only in the renderer.

MOVEOff-screen
Keep moving toward a valid range.
ENTERBody is visible
Use a small edge margin.
CHECKClear sight
Wall or live box can block the shot.
WARNLock the attack
Show the real live area.
FINISHStay committed
Do not cancel when the body leaves view.
Off-screen warning exception: allow it only for a boss or fixed facility. The attack area must cross the screen. Show one clear edge arrow and the exact danger area. Normal enemies do not need attack-route UI.

07 · Bosses

Bosses need new rules, not only a new attack order.

Every boss has four direct attacks and two timed background attacks. Phase 2 and Phase 3 mostly reorder the same four direct attacks. Every boss also creates two external objective objects at each phase.

AS-IS

Later phases reduce the rest gap and run background attacks more often.

The direct attack set does not gain a new rule.

All five bosses repeat the “find and break two objects” structure.

The result can feel weak even when numbers go up.

TO-BE

Phase 1 teaches one boss idea.

Phase 2 adds one new rule.

Phase 3 combines two learned rules.

Use external objective objects for only one or two bosses.

Boss pattern library

These are simple rule parts. They are not copied art. A boss should combine a small set and give each set a fair answer.

01 · AIM

Aimed stream

One line follows the last player position. Move sideways after the lock.

02 · AIM

Aimed fan

Three to seven shots make a cone. Move through the large gap.

03 · SPACE

Fixed fan

Shots use fixed angles. Learn the safe lanes before the shot.

04 · SPACE

Ring burst

Shots leave the boss in all directions. Stay back or find one gap.

05 · SPACE

Spiral

The shot direction turns over time. Follow one safe lane slowly.

06 · AIM

Rotating turret

A weapon turns, locks, then fires. Cross the line before the lock ends.

07 · SPACE

Sweeping beam

A long beam moves across the field. Use the open end, cover, or one planned dash.

08 · TIME

Ground marker

A circle or lane is marked, then hits. Leave early.

09 · MOVE

Charge

The boss locks one direction and rushes. Step aside, then punish recovery.

10 · MOVE

Jump and slam

The landing area is shown first. Leave it and attack after landing.

11 · AIM

Homing set

Slow shots follow for a short time. Group them, then cut across.

12 · SPACE

Bouncing shot

A shot hits a wall and returns. Read the next path, not only the first path.

13 · SPACE

Moving hazard lane

A dangerous strip moves through the field. Choose the safe side early.

14 · PRIORITY

Limited summons

A small support group arrives. Kill the key unit or survive its short timer.

15 · CHOICE

Breakable weapon

Break one visible weapon to remove one attack. The choice is useful, not required travel.

16 · TIME

Open weak point

The core opens for a short bonus. Normal damage still works when it is closed.

17 · PHASE

Phase handoff

A health point adds one new rule. Show a clear change cue.

18 · SPACE

Arena squeeze

Two slow dangers reduce safe space. Pick a lane and save dash for the exit.

08 · Other problems

Five more issues need attention.

A

Crowd readability has no safe falloff.

At high pressure, bodies overlap into one red mass. Important threats, drops, and warnings lose order. Add a crowd display rule: keep boss, target, committed danger, and player above all optional detail.

B

Hit and kill confirmation is too quiet.

Many impact, death, pickup, and secondary events are intentionally hidden. This makes different weapons feel closer than their rules.

C

Tests prove safety, not fast human reading.

Current checks cover collision, placement, timing, and exact replay. Add a short visual test: can a player name every blocker, live terrain effect, owner, and committed danger in one second?

D

Review assets are not reaching runtime.

The repository has wall candidates and external sources. Most are still review-only. The process needs one small approved family at a time, starting with outer wall, inner wall, cover, and floor.

E

The product document no longer matches the requested game.

The current document keeps one physical map and blocks extra map systems and new boss families. Change that owner first, or future work will keep pulling in two directions.

09 · Recommended order

Fix meaning before polish.

This order lowers rework. It is a direction, not a full execution plan.

P0

Change the product decisions

Lock the map lifetime table, box relocation rule, enemy visibility gate, stage palette cap, and boss objective policy in the product spec.

P1

Make meaning clear

Split wall roles. Add the basic effect shape set. Stop normal off-screen attack starts. Restore small hit and kill feedback.

P2

Add controlled change

Use stage tactical packages. Add safe box relocation. Keep major walls stable for the run.

P3

Reduce learning load

Cap the stage enemy palette. Keep two familiar roles and add one new role at a time.

P4

Rebuild boss growth

Use the pattern library. Add one rule per phase. Keep external nodes for only selected bosses.

P5

Polish the proven shapes

Adapt or author final art only after the simple version passes crowded-play and grayscale checks.

Simple success rules

  • A player can tell outer wall, inner wall, cover, and special terrain in one second.
  • A shield can never look like a damage aura.
  • A normal enemy starts zero attacks while its body is off-screen.
  • A stage uses no more than six total enemy roles.
  • Each boss phase adds one rule or one real combination.
  • Box movement never increases the reward budget.
  • The same seed still makes the same safe result for a retry.

Recommended human choices

Keep main walls for the full run

Recommended. Let small tactical objects change at stage boundaries.

Use external art as source material

Recommended. Adapt it to Cardborne. Do not ship a pack unchanged.

Move only unopened, unseen normal boxes

Recommended. Keep a finite stage reward budget.

Use external nodes on one or two bosses

Recommended. Give other bosses a movement or timing weakness.
