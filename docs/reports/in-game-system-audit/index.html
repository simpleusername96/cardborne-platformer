01 · AS-IS → TO-BE

The current art hides size, meaning, and movement.

The new direction must stay as simple as the craft and enemies. It must also show what happens when an image repeats, stretches, or fills a large game area.

AS-IS

  • Each floor tile looks like its own framed card.
  • Outer walls, inner walls, and cover do not have a clear size order.
  • Barrier and damage effects often read as the same ring.
  • Old sheets hide repeat and scale inside small equal boxes.
  • The closest concept mixes the map, assets, and effects in one unclear image.
  • Upgrade cards hide weapon slots and repeat similar art.

TO-BE

  • The floor reads as one calm field, even when it repeats.
  • The outer wall is heavy. Inner cover is smaller and sparse.
  • Each effect result has its own clear base shape.
  • Every final approval proof must show real game size and full live area.
  • Map, asset, effect, repeat, and scale questions are shown separately.
  • Upgrade cards show behavior and all build limits.

04 · Already locked

These rules control every new visual.

Locked

No SVG or ImageMagick art

SVG and ImageMagick may not draw, invent, repair, trace, restyle, or finish any player-facing shape. This includes map art, effect bodies, warnings, icons, and UI chrome.

Locked

Keep movement open

Walls give short cover. They do not draw a route. Every combat pocket needs more than one wide escape side.

Locked

Match the simple game

Use a few large geometric masses. Do not make detailed tile art beside simple craft and enemies.

Locked

Show real use

A repeated tile is shown repeated. A large effect is shown at its full radius. A stretched asset is shown stretched.

Locked

One effect means one visual family

The same result keeps the same base shape. Different results do not share the same ring or burst.

Locked

Show who owns the effect

Player and enemy versions use the same effect family, but change both color and one clear shape mark.

Locked

Art follows game truth

Visible size, warning area, collision, and effect area must agree. Art never creates a new wall or safe area.

Locked

No decorative noise

No tiny panels, repeated lamps, nested borders, rings, or detail that has no game meaning.

05 · Do not / allowed exceptions

Keep the bans simple and the exceptions narrow.

Do not

  • Do not use SVG or ImageMagick to make or repair visual geometry.
  • Do not make a maze, a route wall, or a dead end.
  • Do not use detailed tiles, tiny panels, lamps, or random seams.
  • Do not bring back repair or attack pads that reward waiting.
  • Do not use one ring for barrier, damage, dash, and arrival.
  • Do not use color as the only player/enemy mark.
  • Do not approve an asset from a small isolated sample.

Allowed exceptions

  • ImageMagick may only crop, resize, change file format or alpha, check pixels or size, and place already-authored PNGs with plain evidence labels.
  • A barrier may use one support ring.
  • A teleport gate may use one full circular portal.
  • A meteor may show its full path because it is a large moving world danger.
  • An off-screen boss or large device may show a long attack path.
  • Live radius, beam width, and cooldown fill stay code-made so they match the game.
  • An outside asset may be used only after it is licensed, simplified, and tested in the real scene.

01 · Short answer

The problems are real. Two earlier recommendations were wrong.

Map rules do exist. But cover should give room to dodge and break enemy fire. It should not force a route. Also, floor and wall art does not need to join at every edge. It only needs to stay calm and clear in its real use.

Map Partly true.

Safe random placement exists. But support pads reward waiting, and some walls form closed reward pockets.

Effects Confirmed.

A shield and a damage aura both use the same mint ring. Many hit effects draw nothing.

Enemies Confirmed.

Normal attacks check range and clear sight. They do not check if the enemy is on screen.

Bosses Confirmed.

Each phase is faster, but it mostly changes the order of the same four attacks.

The first blocker is a product rule conflict. The current game document says no new map-generation system and no new boss-pattern family without a spec change. The requested direction needs that document to change before code work starts.
The design discussion now has its own report. This page keeps the visual and UI audit. The separate game design reset report covers neutral terrain, fixed enemies, items, and upgrades.

What is true now

Question Current truth Meaning
Is the map random? Yes, inside a fixed set of safe sockets and cover choices. The system is not missing. It is too fixed and too similar.
Does pad relocation fix the problem? No. Repair and overdrive pads relocate on a schedule, but their live zones still reward waiting. Remove or replace the waiting rule before making new pad art.
Do item boxes move? No. Their position is chosen when the stage layout is built. A new finite relocation rule is needed.
Do mobile enemies chase? Yes. Mobile roles have pursuit movement. Fixed towers and mines do not move. The bigger fairness problem is off-screen attack start.
Are bosses immune? No. A sealed boss still takes 20% damage. The open window takes 155%. The problem is repeated work, not full immunity.

03 · Map and items

The map needs open movement, useful cover, and no dead ends.

The code uses a seed. A seed is a number that can repeat the same random result. It picks one field, eight cover blocks, enemy sockets, six loose items, and eight boxes. It also checks walkable space and safe distance. This is good. The design around those safe positions needs to change.

AS-IS

The three fields use almost the same large frame and center pattern.

Outer walls and inner structural walls use the same wall image.

Floor panels look like many dark UI cards. They are stronger than some game objects.

Repair and overdrive fields ask the player to stay in one small area while enemies close in.

Two reward rooms use walls and one entrance, so they create dead-end pockets.

Boxes stay where the stage put them.

TO-BE

Keep safe random rules and repeatable retries.

Keep the field wide and fast. Do not build route puzzles.

Use sparse cover islands to block fire and give a short dodge break.

Remove every dead end. A player must always have more than one escape side.

Remove or replace repair and overdrive pads before making new art for them.

Move only unopened, off-screen boxes. Never create free extra rewards.

Fresh full-field screens

Correction to the earlier report: cover does not exist to make a route. It exists to cut enemy fire, stop a direct rush, and give the player room to dodge. Internal walls must not make corridors, traps, or dead ends. The outer boundary can stay, but open space is the main play space.

What should change, and when?

Time Keep Change Why
Full run Field identity, outer boundary, sparse large cover, worn-tile positions Nothing here The player can learn safe dodge spaces without being trapped.
New stage Open travel space and clear spawn space Neutral devices, loose items, normal boxes, Arc Surge positions, and Transit Gate pairs The field changes without moving solid cover during combat.
Timed Total reward budget One unopened box, hazard cycles, and a clearly warned moving event such as a meteor Live change gives the player a reason to keep moving.
Never Free escape and one shape = one game meaning Do not make dead ends or reuse one cue for another rule The game stays fast and readable.

A better random field model

Let code choose safe positions and simple shapes. Do not build a maze.

Safe box relocation

Recommended box rule

  1. Keep a fixed reward budget for the stage.
  2. After a fixed timer, select one unopened normal box.
  3. Move it only if it is off-screen and far from the player.
  4. Use a reachable socket that was not used recently.
  5. Never move the two boxes inside reward rooms.
  6. Do not replace a box after the player opens it.

Can Cardborne use external assets?

Yes, but they are not the first need. The current craft, enemies, items, and fields use very simple geometry. Large flat shapes drawn by Godot may match them better than a detailed tile pack. External art can still be a shape reference or a source kit. It should not set a more detailed style for the map.

Use this intake rule

  1. Save the official link and license.
  2. Save the source file hash.
  3. Select only the needed part.
  4. Reduce the source to Cardborne's simple shape level.
  5. Adapt camera, size, color, and edge style.
  6. Compare AS-IS and TO-BE at real game size.
  7. Approve the exact final file before runtime use.

04 · Effects

Game meaning needs a small shape language.

The first goal is not beautiful effects. The first goal is complete and stable meaning. One rule should always use one base shape. A different rule should use a different base shape.

AS-IS

The barrier is a mint ring at radius 61.

Ion Field is also a mint ring, only larger.

Many projectile hits, weapon hits, enemy deaths, and pickups are set to “show nothing.”

The effect event does not carry a clear player or enemy owner field.

TO-BE

Use simple code shapes first.

Give every effect a base shape, owner sign, live size, and life phase.

Keep the base shape for the same effect.

Change both color and a small notch or direction mark for player and enemy ownership.

05 · Design reset — AS-IS → TO-BE

Keep the whole game as simple as its current craft and enemies.

The map should not look like a different game. Current actors, items, pads, and many effects use large, simple shapes. New world art and UI must use the same low level of detail.

AS-IS design mistake

The first candidate sheets show every object inside the same size box.

They make walls and facilities more detailed than the current actors.

They assume that every floor or wall image must join to the next image.

They judge a large field effect like a small icon.

TO-BE visual rule

Use a calm base floor and a few separate large shapes. Edge joining is optional.

Use simple filled geometry for boundary, cover, warnings, and live areas.

Show every object next to the real player craft at its real size.

Show large effects at their full game area, not inside an icon box.

07 · Enemies

Normal enemies should enter the screen before they start an attack.

Current normal attacks use distance and clear sight. They do not require the enemy body to be visible. Mobile pursuit already exists. The fix belongs in attack permission, not only in the renderer.

MOVEOff-screen
Keep moving toward a valid range.
ENTERBody is visible
Use a small edge margin.
CHECKClear sight
Wall or live box can block the shot.
WARNLock the attack
Show the real live area.
FINISHStay committed
Do not cancel when the body leaves view.
Off-screen warning exception: allow it only for a boss or neutral fixed device. The attack area must cross the screen. Show one clear edge arrow and the exact danger area. Normal enemies do not need attack-route UI.

08 · Bosses

Bosses need new rules, not only a new attack order.

Every boss has four direct attacks and two timed background attacks. Phase 2 and Phase 3 mostly reorder the same four direct attacks. Every boss also creates two external objective objects at each phase.

AS-IS

Later phases reduce the rest gap and run background attacks more often.

The direct attack set does not gain a new rule.

All five bosses repeat the “find and break two objects” structure.

The result can feel weak even when numbers go up.

TO-BE

Phase 1 teaches one boss idea.

Phase 2 adds one new rule.

Phase 3 combines two learned rules.

Use external objective objects for only one or two bosses.

Boss pattern library

These are simple rule parts. They are not copied art. A boss should combine a small set and give each set a fair answer.

01 · AIM

Aimed stream

One line follows the last player position. Move sideways after the lock.

02 · AIM

Aimed fan

Three to seven shots make a cone. Move through the large gap.

03 · SPACE

Fixed fan

Shots use fixed angles. Learn the safe lanes before the shot.

04 · SPACE

Ring burst

Shots leave the boss in all directions. Stay back or find one gap.

05 · SPACE

Spiral

The shot direction turns over time. Follow one safe lane slowly.

06 · AIM

Rotating turret

A weapon turns, locks, then fires. Cross the line before the lock ends.

07 · SPACE

Sweeping beam

A long beam moves across the field. Use the open end, cover, or one planned dash.

08 · TIME

Ground marker

A circle or lane is marked, then hits. Leave early.

09 · MOVE

Charge

The boss locks one direction and rushes. Step aside, then punish recovery.

10 · MOVE

Jump and slam

The landing area is shown first. Leave it and attack after landing.

11 · AIM

Homing set

Slow shots follow for a short time. Group them, then cut across.

12 · SPACE

Bouncing shot

A shot hits a wall and returns. Read the next path, not only the first path.

13 · SPACE

Moving hazard lane

A dangerous strip moves through the field. Choose the safe side early.

14 · PRIORITY

Limited summons

A small support group arrives. Kill the key unit or survive its short timer.

15 · CHOICE

Breakable weapon

Break one visible weapon to remove one attack. The choice is useful, not required travel.

16 · TIME

Open weak point

The core opens for a short bonus. Normal damage still works when it is closed.

17 · PHASE

Phase handoff

A health point adds one new rule. Show a clear change cue.

18 · SPACE

Arena squeeze

Two slow dangers reduce safe space. Pick a lane and save dash for the exit.

09 · Other problems

Five more issues need attention.

A

Crowd readability has no safe falloff.

At high pressure, bodies overlap into one red mass. Important threats, drops, and warnings lose order. Add a crowd display rule: keep boss, target, committed danger, and player above all optional detail.

B

Hit and kill confirmation is too quiet.

Many impact, death, pickup, and secondary events are intentionally hidden. This makes different weapons feel closer than their rules.

C

Tests prove safety, not fast human reading.

Current checks cover collision, placement, timing, and exact replay. Add a short visual test: can a player name every blocker, live terrain effect, owner, and committed danger in one second?

D

Art was explored before the game roles were stable.

The old sheets try to solve wall, floor, pad, and effect art at once. Set the gameplay role, real size, and runtime use before making the next candidate.

E

The product document no longer matches the requested game.

The current document keeps one physical map and blocks extra map systems and new boss families. Change that document first, or future work will keep pulling in two directions.

10 · Recommended order

Fix meaning before polish.

This order lowers rework. It is a direction, not a full execution plan.

P0

Record locked G1 and G2

The short game brief now locks or delegates every product rule in this reset.

P1

Update the main product rules

Write the approved field, neutral device, item, enemy, boss, and upgrade rules into the product specification before code work.

P2

Fix combat meaning

Remove dead ends, add safe box relocation, convert fixed enemies, stop normal off-screen attack starts, and restore small hit and kill feedback.

P3

Reduce learning load

Cap the stage enemy palette. Keep two familiar roles and add one new role at a time.

P4

Rebuild boss growth

Use the pattern library. Add one rule per phase. Keep external nodes for only selected bosses.

P5

Make new visual tests

Use simple geometry at real game size. Show actual repetition, gaps, stretch, movement, and large areas only where the approved rule needs them.

Simple success rules

  • The player can move fast through the field without a dead end.
  • Cover gives a break from fire without forcing a corridor.
  • A shield can never look like a damage aura.
  • A normal enemy starts zero attacks while its body is off-screen.
  • A stage uses no more than four mobile enemy roles. Neutral devices do not count as enemies.
  • Each boss phase adds one rule or one real combination.
  • Box movement never increases the reward budget.
  • The same seed still makes the same safe result for a retry.

Defaults already set

Keep the field open

Locked by user feedback. Use sparse cover islands and remove dead-end reward rooms.

Use simple geometry first

Locked by user feedback. External art must be reduced to the same simple style.

Move only unopened, unseen normal boxes

Delegated default. Keep a finite stage reward budget.

Use external nodes on one or two bosses

Delegated default. Give other bosses a movement or timing weakness.
