0회

현재 측정의 원거리 공격

성능 캡처에서 원거리·지역통제 공격이 발생하지 않았습니다. 프레임은 좋아 보여도 완전한 전투 부하는 아닙니다.

가장 심각한 공정성 결함: 현재 렌더러는 적 포격의 경고 시간이 남아 있을 때 위험 영역을 숨기고, 피해가 활성화되는 순간부터 보여 줍니다. “보이는 순간 맞는다”는 피드백과 정확히 일치합니다.

Current state

현재 스쿼드와 전투 로직에서 확인한 문제

스폰

  • 첫 팩 6기, 이후 팩은 보통 4–8기입니다.
  • 스테이지가 세 family를 고정하고, 팩은 그중 하나를 순환합니다.
  • 방출형 팩에 방어형을 붙이지만 family와 trait가 팩 단위라 방어형이 잘못된 메타데이터를 물려받습니다.
  • trait 선택식은 기본/trait A/trait B를 4:3:3으로 만들지만, 완전한 독립 확률이 아니라 결정적 해시입니다.

행동

  • 추격형과 돌진형은 집결·대형 위치를 우선할 때 유저에게서 비켜납니다.
  • 방어형과 조정형은 이동 분기 뒤 즉시 반환되어 직접 공격 상태로 들어가지 않습니다.
  • 방어형의 “원거리 앞을 막는다”는 좌표 계산은 있으나 페어링과 메타데이터가 불안정합니다.
  • trait별 PNG 선택 함수는 있으나, 입력 identity가 틀려 같은 family/trait처럼 보일 수 있습니다.

trait 확률

family마다 별도의 10회 셔플백을 사용해 기본 4 : trait A 3 : trait B 3을 보장합니다. 독립 난수보다 긴 미등장 구간과 몰림을 줄이면서 요청한 확률을 유지합니다. 온보딩 중에는 학습을 위해 기본 trait만 사용합니다.

Visible roles

모든 family가 플레이어에게 읽히는 역할을 갖습니다

추격형·돌진형

집결 위치가 접근을 가로채지 못하게 합니다. 회복 이동도 유저 방향 성분을 항상 양수로 유지합니다. 충돌이나 실제 공격 커밋만 예외입니다.

방어형

같은 스쿼드의 방출형 앞을 막습니다. 보호 대상이 살아 있으면 추격하지 않습니다. 대상이 없을 때만 0.60초 예고의 방패 돌진으로 유저를 공격합니다.

조정형

지원 trait를 유지하면서 0.80초 예고, 피해 12, 속도 420의 직접 탄환 공격을 추가합니다. 성능 시나리오에서도 반드시 공격 커밋이 나와야 합니다.

방출형 포격

포격 trait를 이동 탄환이 아닌 표시된 지면 타격으로 바꿉니다. 공격 준비와 피격 사이에 0.75초를 추가하고, 경고 중 정확한 피해 범위를 계속 표시합니다.

trait PNG

5 family × 3 tier × 기본/trait A/trait B, 총 45개 identity를 모두 검사합니다. 같은 family라도 trait가 다르면 서로 다른 PNG 경로와 content hash를 가져야 합니다. 런타임 색상 변경으로 대체하지 않습니다.

Implementation order

실행 순서와 완료 조건

PHASE 0

용어 전면 변경

코드 ID, 상수, PNG와 import, 로컬라이제이션, 문서, 테스트, 캡처 스키마를 emitter/방출형으로 바꿉니다. 추적 텍스트와 경로에 기존 토큰이 0개여야 합니다.

PHASE 1–2

텔레메트리와 스폰 소유자 분리

순수 composition 모듈을 만들고, encounter runtime은 킬 게이트와 입장만 소유합니다. 온보딩, 10팩 백, 페어링, coordinator 조건을 시드 테스트로 증명합니다.

PHASE 3–5

행동·XP·전투 압박 구현

근접 접근, 방어 위치, 직접 공격, trait PNG, XP 구간, 투사체, 포격 예고와 피해 구간을 책임별로 수정합니다.

PHASE 6

통합 검증과 성능 증명

실제 공격 부하가 있는 deterministic capture, Web export, built Web 확인, clean native 60초 측정으로 닫습니다. combat batch는 80 이하여야 합니다.
